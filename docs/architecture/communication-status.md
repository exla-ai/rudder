# Rudder v4 communication and product-flow completion audit

2026-11-01. Read-only review of PLAN.md §§10,16,17,18, current source, regression definitions and retained evidence. No checks, providers or models were run. “Proven” means the bounded component behavior described below; it does not mean current-stock, macOS, Cloud or full-v4 qualification. Older evidence remains bound to its recorded source/profile. Root's current release/runtime work is outside this audit.

## Requirement assessment

**Durable conversations: core proven; delivery experience incomplete.** `engine/src/journal/mailbox.rs` persists addressed envelopes, correlated replies and delivery intent transactionally, bounds queues, preserves conversations during informational supersession, and advances contiguous receipt cursors. `ack_message` (line369) records scoped receipt, explicitly not model adoption. `engine/src/agent_api.rs::call` exposes send/ask/reply/inbox/ack/await/status with authenticated attempt identity and bounded waits. Meaningful coverage: `engine/tests/journal_durability.rs` tests atomic outbox rollback, ACK holes, original-attempt replies, expiry, supersession and byte capacity; `engine/tests/agent_api_tools.rs` tests asynchronous ask/reply without implicit ACK, cancellation under SQLite contention and identity/epoch refusal. `journal_crash.rs` covers process exit and uncertain effects. The implementation record at `docs/architecture/implementation.md:1560` explicitly says ordinary mail still requires inbox/ack: automatic wake is not shipped. Thus durable storage is ahead of the intended conversational workflow.

**Shared decisions: local authority core proven; richer communication state unverified/incomplete.** `journal/decisions.rs::accept_decision` compares delegated topic versions; `integrate` (line187) fences exact roots, relevant versions and owner authority. `journal_durability.rs:782–953` covers competing decisions and invalidation racing final integration. Ordinary conversation cannot accept a decision. However `AgentApi`'s `AckArgs` carries only `message_id`; `ack_message` stores no observed topic-version vector. The planned subscription/relevance delivery, wait-cycle/blocker routing and coupled source-plus-conversation fork checkpoint were not established by reviewed production callers/evidence. These should remain open §10 requirements, not inferred from generic journal durability.

**Active steer/interrupt/resume: bounded adapter behavior proven; full workload settlement unverified.** `native/src/fabric_runtime.rs::dispatch` (line1316) checks capability, sender/recipient epochs, original acceptance budget and target thread/turn; `apply_lifecycle` distinguishes interrupted, idle and completed states. `fabric_runtime_tests.rs` covers stale/foreign targets, stopped-work resurrection and unsupported Codex version evidence. `agent_link_codex_protocol_integration_tests.rs::actual_codex_loopback_adapter_controls` uses the official CLI and production Rust actor; an empty interrupt RPC ACK is held separate from terminal confirmation. Actual provider steering/same-thread resume is retained in `examples/agent-runtime/evidence/2026-10-30/README.md`. The implementation record expressly warns that Codex turn interruption can leave a yielded shell running until process cancellation/shutdown. Therefore interruption is not proof all tool effects stopped. End-to-end interrupt-then-steer ordering, competing-peer arbitration/loop bounds, user-stop preservation and child/tool reconciliation still need qualification through the actual managed owner path.

**Backend injection: Codex has a concrete profile; Claude Channels production activation incomplete.** Codex app-server steering has the actor/protocol coverage above. `native/src/agent_mcp.rs` implements opt-in `--channel`, declares `claude/channel` and emits peer-data notifications without ACKing them. But `fabric_runtime.rs::configure_agent_tools` (line2100) launches the MCP server without `--channel`; common tool registration alone does not activate Channels. A separate Claude SDK/protocol bridge exists. `verification-native-claude-protocol-working.json` records official Claude2.1.316, actual Rust actor/file edit, typed steering, held terminal confirmation and joined children, using a synthetic provider/fixture RPC relay. It explicitly sets `claudeSupported:false` and excludes production launch-wrapper, managed guest, real authentication and production activation. This is valuable component proof, not a qualified Channels/default-Claude delivery path. ACP and optional notification-only injection are not established qualifications.

**Natural task entry and slash simplification: implemented subset; complete retirement incomplete.** `src/task-routing.ts::classifyTaskRoute` and `native/src/task_routing.rs` share deterministic discuss/direct/decompose behavior. `tests/task-routing.test.mjs` covers no-key/no-network defaults, read-only preservation, redaction, typed classification and visible timeout fallback. `tests/tui/task-routing.test.mjs` checks discussion cannot approve workers and retired commands launch no work. `app_tests.rs::slash_palette_keeps_five_canonical_entries_and_preserves_typed_aliases` covers the small palette. `main.rs:12048` retains `/plan` as a compatibility alias; `/gam` and `/nudge` show retirement notices. Yet `/tell` still calls `tell_gam_reviewer` at12043; GAM modules and generated `RUDDER.md`/`DECISIONS.md` writers (`src/surfaces.ts`) remain. They need consumer/migration accounting before removal. A single versioned operation registry shared across native, CLI, help and completion was not established. This is public-surface simplification, not completion of §16's physical removal/migration gates.

**Automatic planning: routing and initial approval covered; persistent ownership/replanning incomplete.** `tests/tui/plan-pipeline.test.mjs` requires approval, actual isolated worker outputs and final main-checkout merge. Optional Decisions classification requires explicit `RUDDER_TASK_ROUTING=decisions` and `OPENAI_API_KEY`; default subscription users do not depend on an extra API credential. No retained classifier calibration proves real misroute/latency/cost targets. The implementation record at1098–1117 explicitly limits persistent single-owner integration and standalone CLI/board migration: home ingress routes natively, while legacy sails reject discussion/planning and local `/cloud` still reaches that legacy path. Versioned durable approval scope, budget/contract-preserving replanning and stopped/completed-child preservation are not established end to end.

**Compact prompt: source behavior proven; efficiency outcome unverified.** `native/src/tasks.rs::main_task_prompt`/`execution_prompt` provide short role contracts; planner excerpts are bounded. `app_tests.rs:8675`, `tests/run-context.test.mjs` and `tests/context-audit.test.mjs` cover compactness, ownership and context handling. `docs/architecture/prompt-context.md` records literal-byte reductions and explicitly disclaims measured latency/task-speed improvement. Actual backend context-token/cache-hit/startup measurements and E6 offline/fallback qualification remain necessary before retiring coordination files.

**Tailscale/private previews: useful subset proven; device/new-runtime qualification open.** `cloud/worker/home.mjs::startTailscale` (line1526) reuses persisted state, probes live status and bounds asynchronous commands. `tailscale-previews.mjs::createTailnetPreviews` requires HTTP readiness and successful private Serve, persists owned routes before effects and revokes stale PID/project routes. `src/cloud.ts`'s preview path checks project, local tailnet visibility and reachability before opening. `tests/tailscale-preview.test.mjs` covers attribution collisions, stale listeners, private fallback, owned cleanup and real bounded loopback probes. The implementation record reports an actual userspace/Serve check but no laptop/phone access. `worker-execution.md:145` explicitly leaves preview attribution through the trusted execution/view mapping open. Private connectivity does not prove ACL authorization or new namespace/attempt attribution.

**Cloud buffering: byte-stream transport proven; full §18 protocol/observability incomplete.** `cloud/worker/terminal-transport.mjs::createTerminalTransport` provides connection-local UTF-8 decoding, batching, bounded backpressure, stale-socket fencing, exit ordering and repaint recovery. `tests/cloud-terminal-transport.test.mjs` covers these failures plus real WebSocket/PTY paths; the implementation record reports VM checks. Repaint-after-overflow is not a sequenced snapshot/cursor replay protocol. That protocol and per-view recovery guarantees were not established. `src/cloud.ts:3635` has real RTT/echo probes with p50/p95, but not correlated input→relay→PTY→paint traces/p99 or retained real-device sleep/reconnect/slow-observer qualification.

## Next three bounded work packages

1. **Finish mailbox-to-session delivery and interruption settlement.** Wire an explicit qualified backend delivery profile, including a supported Claude Channels activation/fallback decision; retain original message identity through write, ACK and restart. Add real-session tests for idle wake, busy queued mail, ACK holes, crash after write, stale epochs, interrupt→confirmed stop→steer, user-stop conflicts and yielded child processes. Neither a JSON transport ACK nor a returned model turn may close the tool/process settlement gate.

Test the same discuss/direct/decompose request through native, home, local Cloud forwarding and CLI; preserve chosen checkout/backend/location, completed work and authorization during replanning. Keep Decisions optional; qualify calibration separately.
3. **Qualify the actual interactive Cloud experience.** Bind previews to trusted managed attempt/view identity; specify sequenced terminal recovery and bounded per-view queues. Exercise a real Mac and phone on an authorized tailnet: login reuse, ACL denial, HTTPS/private fallback, PID/port reuse, namespace listeners, sleep/reconnect, large paste/scroll, slow viewers and stale Ctrl+C refusal. Retain source/image identity, bounded memory and correlated p95/p99 input-to-paint measurements. Required prerequisites are those devices, tailnet/ACL access and certificate capability, not another storage component pass.
