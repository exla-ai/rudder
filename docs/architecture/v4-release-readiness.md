## Evidence tooling and exact-source capture

`scripts/v4-release-readiness/catalog.mjs` names the experiments, requirement identities, locality and bounded local commands. The verifier binds evidence to jj revision plus SHA256/size/type of product, test and release inputs. Documentation/generated ownership text is excluded from the tree digest, but an exact revision still binds each receipt. Binary/package/image identities must also appear in the underlying external evidence.

```sh
node scripts/v4-release-readiness/readiness.mjs catalog
node scripts/v4-release-readiness/readiness.mjs capture /private/evidence/candidate.json
node scripts/v4-release-readiness/readiness.mjs check production-ts /private/evidence
node scripts/v4-release-readiness/readiness.mjs report /private/evidence
```

The last command exits 1 while any experiment or delivery requirement is missing. Exit 2 means invalid input/source capture. Do not rerun costly local checks with unchanged inputs just to collect a different wrapper format; retain the existing scoped logs and have the coordinator review their limits. The candidate directory contains `candidate.json`, receipt JSON and contained artifact files; do not mix other JSON documents into it.

Local check receipts always have `requirements: []`; positive executed-test counts and zero failed/skipped cases are required. They cannot auto-promote any E gate. External observations require a coordinator-reviewed receipt with `version: 1`, exact `source: {revision, tree_sha256}`, UTC `started_at`/`finished_at`, `result: "passed"`, `exit_code: 0`, `platform: {os, arch, kernel}`, `scope`, nonempty known `requirements`, positive `samples`, zero `failed`/`skipped`, `review: {accepted: true, owner, limits}`, and contained `artifacts: [{path, sha256, bytes}]`. Real Mac receipts also record `hardware_arch` matching `arch` and `translated: false`. Two-worker/restore receipts include distinct `workers` with `machine` and `volume` identities and destination `initially_empty: true`. Never put credentials in identities or artifacts. Relevant scopes include `two-fly-workers`, `replacement-worker`, `managed-root`, `real-codex`, `real-claude`, `real-laptop` and `real-browser`.

This is a consistency checker, not an authenticity oracle: typed JSON, a digest, human review text, or exit zero cannot make a fabricated observation true. Review actual logs, platform/backend behavior, sample limits and provider evidence before accepting a requirement. Source changes invalidate affected receipts; do not relabel older observations as new source. The tool keeps Mac/registry/deployment delivery requirements separate from backend/local integration.
