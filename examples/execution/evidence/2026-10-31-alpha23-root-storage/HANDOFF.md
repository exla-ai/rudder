# Disposable global RO mount capability canary

Prepared for Root only. No physical run has occurred for this adaptation. Local validation is five `node --check` passes and eight fake-transport scenarios; no provider, auth, build, smoke-command, mount, or unmount operation ran. Import/default dispatch has no effects.

Only the five top-level `.mjs` modules from `/workspace/rudder-alpha23-candidate2-worker-smoke` were adapted. `baseline/` preserves those exact source modules; `module-changes.patch`, `manifest.json`, and `SHA256SUMS` seal the changes. `transport.mjs` is byte-identical. The source's existing physical smoke receipts are not proof for these new guest/controller bytes.

Root may run with its existing authorized provider environment:

```sh
node /workspace/rudder-seed-ro-mount-canary/controller.mjs --run --image registry.fly.io/rudder-workers-exla:4.0.0-alpha.23 --revision ca3eb6ce2c663b6c5069ce2adc094c8b64f8af87 --digest sha256:ea39437f476ea1c704afb7eca6596d79df9dfada97ae9dde74141562e7394f80
```

The controller generates a fresh UUIDv4 unless supplied `--nonce`. Do not reuse a nonce. It retains the original exact image/revision/digest, source-function hash, config, nonce, Machine ID and live instance guards. Protected home7 ID `8edd225a7d0378`, instance `01M670MG4A8E0DWE9GA1C0PQ92`, and its image digest remain forbidden. Empty app secrets are checked twice, before create and before guest admission. No worker/supervisor/profile or model module is loaded.

The root guest records real UID/GID, all five capability sets and current mount namespace. Effective CAP_SYS_ADMIN bit21 is mandatory; missing capability is a failure, not a skip. It creates a fresh `/workspace/seed-ro-<nonce>/objects` target, mounts a private 16MiB tmpfs with nosuid/nodev/noexec, writes an owner1500 mode0600 fixture while writable, then remounts ro. Root's actual append must fail with `EROFS`, and the fixture hash must remain unchanged. Tool binaries are hashed from fixed root-owned paths. Every mount/remount/unmount uses fixed argv without a shell, a five-second deadline plus a two-second settlement bound, and at most 8KiB from each output stream.

The unchanged setpriv identity boundary launches guestSmoke as UID/GID1500 with cleared groups, all capability sets zero, and NNP1. That child checks the same MNT namespace and tmpfs mount ID, readonly/nosuid/nodev/noexec flags, capacity, fixture ownership/hash, and its own actual append `EROFS`; it then runs the original seven bounded smoke commands. Root only attempts normal unmount after the real child has both exited and closed its pipes, and after all root mount commands have settled. It checks mountinfo absence and unchanged MNT namespace after unmount. No lazy/forced unmount is used. Unsettled children or commands retain explicit incomplete-cleanup facts for owned-VM destruction.

`guest-proof.json` preserves partial root/child/actions/cleanup facts even on rejection. `validateProof` checks the seven original smoke commands; `validateReadOnlyProof` independently checks the RO proof, including exact argv and settlement receipts. `report.json` separates `smokePassed` and `rootStoragePassed`; `qualified` also requires exact-owned VM destruction, two fresh absence inventories, and the original lifetime bound. A missing CAP, mount failure, wrong errno, changed namespace, missing settlement, or failed unmount cannot qualify. Original uncertain-create reconciliation and foreign-instance refusal are preserved. Controller cleanup always runs after an attempted create; an unobservable/replaced instance requires explicit reconciliation rather than a guessed destroy.

The controller retains original 220s work/350s cleanup/360s total limits and the root guest's original 300s fuse. Provider output that may contain unrelated home/auth data remains suppressed into byte/hash receipts. Only controlled guest proof and bounded command output are retained. The fuse is an emergency VM lifetime limit, not a successful child or mount cleanup receipt.

Scope is current root storage capability in the disposable worker's inherited MNT namespace, shared with its UID1500 child. It does not attest Fly's outer namespace or implement a persistent storage helper, authenticated seed session, retained production seed owner, `open_retained` handoff, Spec3/backend launch, or preparation reuse. A passing physical result would remove the stock-root mount-capability uncertainty only. Production storage ownership, authenticated lifetime/ACKs, agent reader drain and shutdown recovery remain separate prerequisites.

Mock coverage: ordinary success; old smoke failure with independent valid RO proof; replaced instance refusal; uncertain create observed and cleaned; unobserved create reconciliation; missing RO proof despite valid seven commands; missing root capability; failed unmount absence. Additional pure proof mutations reject `EACCES`, unsettled umount, lazy-umount argv, changed MNT namespace, and oversized capacity. These are input-validation tests, not physical kernel proof.
