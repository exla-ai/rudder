# Root storage IPC component qualification

This modified Main working-tree component passed on a disposable Fly VM on
2026-11-01. It is not a Rudder release or enabled managed startup.

The actual Root service and UID1500 engine authenticated original pidfds,
proc-exe witnesses and SCM credentials. Root verified and imported bytes into
its independent CAS, pinned the immutable seed and mounted it read-only. Two
actual engine-child helpers enrolled before view use, reopened real Git/jj
history and made independent private metadata forks. One helper changed its
private history; its sibling stayed unchanged. Root independently observed
the first helper exit while retaining the sibling, then both successful reaps
and pipe EOF. A second cancelled preparation retained the original owners.

Normal retirement remains blocked. The service and engine held their actual
mount, read, import and source owners until the exact-owned VM was destroyed.
Two independent inventories verified VM absence. This test does not prove
normal unmount/unpin, the production launcher, Spec3, an agent model run or
accepted Journal authority.

The first physical attempt exhausted an overly frequent polling schedule. Its
VM cleanup passed. The corrected bounded harness passed on the SAME image,
using 17 provider calls within its 26-call maximum. `prior-attempt.json` keeps
that failure visible.

`source-inputs.json`, `artifact-seal.json` and `derived-image.json` bind the
full frozen working source, compiled libtest ELF and actual image digest.
The ELF is retained privately and is not committed. See
`artifact-origin-clarification.json` for the exact cached compilation order.
`kernel-ipc-receipt.json` contains the actual marker and bounded log hashes;
raw output and provider inventory remain private.

The harness source includes its shared validator and offline scenarios. Run
`node selftest.mjs` for those tests. Actual VM execution requires the exact
sealed ELF/image, Fly access and Root's documented ownership/cleanup gates.
No default activation follows from these files.
